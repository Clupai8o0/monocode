# Personal MonoCode fork

Fork of [hardbeat920/monocode](https://github.com/hardbeat920/monocode) (MIT). Own changes live on the `mine` branch.

| Piece | What it does |
|---|---|
| Projects sidebar | Search, Monos, Projects and sessions; the selected project uses a quiet fill and its row menu holds project settings. Monos and Projects have bounded scrolling to keep sessions reachable. Worktrees and app Settings sit beside notifications in the upper-left toolbar; there is no duplicate project dropdown. Running projects sort by latest run start, with running/needs-you/done counts, and hold their order while being used. The old bottom carousel and duplicate Working agents panel are removed. `src/fork/projects` owns the list. |
| Sidebar design comparison | Open `fork/designs/projects-sidebar.html` offline: the selected Projects layout, project tree, activity-first and current-layout reference, with 16 projects and 64 labelled sample sessions; search, menus, filters and selection work. The real-component test preview is `/tests/browser/workspace-performance.html?projects` on the local Vite server. |
| Notifications | The upper-left title toolbar bell is the single in-app event feed; the duplicate right-side question/approval toast stack is removed. It opens the latest 120 completions, questions and approval requests, even with the sidebar closed; filters and links reopen the session in its owning window, where decisions are answered. `src/fork/notifications` stores local history independently of OS banner permission, shares read state between windows, and respects project mute preferences for unread indicators. |
| HTML file preview | `.html` and `.htm` open in Preview, with Code/Split controls, live draft refresh and reload; review tabs and line links open Code. `src/fork/html` and `src-tauri/src/fork_html.rs` isolate scripts, pause hidden previews and bound retained drafts. Project-relative assets work on macOS/Linux; remote/Windows remain self-contained. External requests and root-absolute asset paths are blocked. |
| Project logos | The existing logo picker and `/operator` agent commands share saved images and optional transparent/light/dark backplates. Idle projects show their logo; busy projects crossfade to the working mascot every six seconds, pausing in hidden windows and respecting reduced motion. Failed images fall back to the mascot. `src/fork/projectLogos` owns agent actions and activity rendering. |
| Provider usage | Installed, visible Claude and Codex balances stay in the footer together with the selected project accounts. Usage refreshes every 15 minutes while visible, or on opening/focus when over five minutes old; windows share account snapshots and reads when Web Locks are available. Failed refreshes retain the last successful age, and unique Codex probe IDs avoid cross-window collisions. |
| Multi-window polling and memory | `src-tauri/src/fork_poll_cache.rs` shares claims/stack reads across windows (10s/30s), coalesces simultaneous requests, and invalidates stack results after stop; manual refresh bypasses the cache. `src/fork/sessionRead.ts` expires full transcripts after 10s and retains at most 32 completed reads per window. |
| Codex desktop integration | `src/fork/codex` supplies current-turn host context; Codex now preserves peer-message envelopes/MCP send receipts and shows artifact links. Effort, mentions, `/operator` and phone access retain their existing controls and permissions; see [capabilities and limits](CODEX.md). |
| Agent-configured Monos | Regular `/operator` sessions can suggest a Mono, then use `monos.list` and `monos.configure` to set up or adjust one when asked. Access stays within the current local project; new habits start paused unless explicitly enabled, and configured habits cannot increase the source session's permissions. Monos must be enabled, and scheduled work runs while the app is open using normal provider allowance. |
| `fork/monocode` | The `monocode` command (symlinked from `~/.local/bin`). Swaps in a staged build if MonoCode is closed, opens it, starts `update.sh` in the background. The app runs it too (`--update`, `--after-quit PID`); see Update from the Dock. |
| `fork/update.sh` | Merges `upstream/main` into `mine`, lets a Claude agent fix conflicts or a broken build, runs `tsc` + `npm test` + `tauri build`, stages the app. Rolls back on failure and sends a notification. |
| Hidden features | `src/fork/hiddenFeatures.ts`: Inbox, Notes and Automations are hidden (not deleted, so merges stay clean). The inbox stops polling and the automation scheduler stops. Off under `vitest` so upstream tests still pass. Set a flag to false to bring one back. The macOS View menu still lists Inbox and Notes; they do nothing. |
| Hidden providers | `HIDDEN_PROVIDERS` in `src/fork/hiddenFeatures.ts`: Devin, Pi, OMP and Fx are left out of Settings, the model picker and orchestration, even if installed. Off under `vitest`. |
| Close badges | `src/fork/closeBadges`: each session card shows Safe, Handover or Not safe, read from the "Close:" line of its last reply (read from the saved transcript once per save, cached in localStorage). The double-tick button by the session filter archives every safe session after a second click; the open, pinned, busy and waiting ones are skipped. |
| PDF preview | `src/fork/pdf`: `.pdf` files open in a viewer in the file pane instead of the editor. pdf.js draws pages onto canvases, loaded only when a PDF is opened, so the app CSP stays unchanged. Zoom with the footer, Cmd+scroll, pinch or the zoom keys. No text selection or links yet. Browser test: `npx playwright test tests/browser/pdf-preview.spec.ts --project webkit`. |
| DeepSeek provider | `src/integrations/harness/providers/deepseek`: runs DeepSeek Harness (`dsh --profile acp`, standard ACP) as a MonoCode agent. Models and reasoning effort come from dsh. dsh sandboxes itself to the workspace and asks no edit approvals, so Supervised and Plan modes are not enforced by it. |
| Stacks panel | `src/fork/stacks` + `src-tauri/src/fork_stacks.rs`: a footer button "Stacks · N up" lists the shared Docker stacks and devices from the vault's `stacks.py list --json`, who holds each, and flags one started by hand that nobody uses (amber). Stop runs `stacks.py stop NAME`, asking first when a session holds it; there is no Start. Polls every 60 s while visible. Hidden if `stacks.py` is missing; off under `vitest`. |
| Table preview | `src/fork/table`: `.csv`/`.tsv` get a Preview/Source toggle with a sortable grid; `.xlsx`/`.xlsm` open in a sheet viewer. Excel is read in the webview with a small zip + XML reader (no new dependency). `.xls`/`.ods` go through the Office preview. |
| SVG preview | `src/fork/svg`: fit, zoom and 1:1, checker/light/dark background, size in the footer. Drawn as an `<img>`, so scripts inside the SVG never run. |
| Notebook preview | `src/fork/notebook`: `.ipynb` Preview shows cells with their saved outputs, read-only. HTML and JavaScript outputs are never rendered; their plain-text version shows instead. |
| LaTeX preview | `src/fork/latex` + `src-tauri/src/fork_latex.rs`: `.tex` opens as code and PDF side by side (Code/Split/PDF). Builds on open and on save with pdflatex, xelatex or lualatex from MacTeX (never latexmk), shell escape off, output in `~/Library/Caches/monocode-fork/latex`. Errors link to their line. Honours `% !TEX root` and `% !TEX program`. Needs MacTeX. |
| Office preview | `src/fork/office` + `src-tauri/src/fork_office.rs`: Word, PowerPoint, OpenDocument, RTF, `.xls` and Pages files are turned into a PDF by headless LibreOffice (own profile, macros stay off) and shown in the PDF viewer. Cached until the file changes. Needs LibreOffice (`brew install --cask libreoffice`). |
| Peer message card | `src/fork/peerMessages`: a message another Claude Code session sends in (`<cross-session-message>`) shows in the chat as a quiet card with the sender's agent mark, name, time and text, instead of being dropped; "Open session" shows only when the sender is a session MonoCode runs. Hooks: `claude.ts` `handleUser`, `AgentTranscript.tsx` (two lines), `child.ts` `sessionIdForPid`. |
| Who's editing what | `src/fork/claims` + `src-tauri/src/fork_claims.rs`: file tabs and Explorer rows get a small tag naming the live session editing that file (folded folders: files under them), from the vault's `claims.py list --json DIR` (read-only). Orange for Claude, blue for Codex, dashed when the edit is in another worktree. Hover shows how long ago and the session's status note. One poll per project every 15 s while the window is visible; off under `vitest`. Hooks: `FileTree.tsx` (context root + tag), `SurfaceTabs.tsx` (tag). |
| Message badge and pane | `src/fork/peerMessages/{peerStats.ts,PeerBadge.tsx,MessagesButton.tsx}`: each session card shows a mail count for messages other sessions sent in since it was last open (amber when one says urgent) and an arrow count for messages it sent to other sessions (not its own subagents). A footer button "Messages · N" lists every message received, newest first, with a filter per project; a row opens the session. Read from each listed card's saved transcript once per save (a working session at most every 30 s); read marks in localStorage. Off under `vitest`. Hooks: `Sidebar.tsx` (beside the close badge), `UsageFooter.tsx` (button). |
| Alerts: counts, banners, re-alert | `src/fork/alerts` + `src/fork/projectStatus`: the project rail's amber badge shows how many agents wait on you, and the window title starts with "N need you ·". macOS banners are on by default (upstream: off); macOS is asked once at launch while the setting is untouched. An approval or question left 5 min (alerts.py's delay) alerts once more: "Still needs you" banner, sound, one Dock bounce; it waits while you look at that session. Off under `vitest`. Hooks: `notifications.ts` (default, `isWindowFocused`), `dockBadge.ts` (count), `TitleBar.tsx` (title), `App.tsx` (`useNeedsAgain`), `capabilities/default.json` (request-user-attention). |
| Handoff indicators | `src/fork/handoff`: a small project tag indicates `.claude/handoff.md`; the large sidebar card is removed from both layouts. Files and the existing handoff machinery remain available. Local folders only; `stat_files` on watched projects every 60 s while visible and on focus. Off under `vitest`. |
| Workspace windows | `src/fork/workspaces` + `src-tauri/src/fork_workspaces.rs`: named workspaces, one OS window each (label `ws-<slug>`, title starts with the name). Each keeps its own layout snapshot and interrupted-turn list in `<app data>/fork-workspaces.db`; `main` and `window-N` keep upstream's single row. Workspaces open at quit reopen at launch; closing one by hand stops that. Footer button (and File > New Workspace… / Workspaces…) lists them: open or bring forward, new, rename, forget a closed one, or a Chrome window with its own profile (`~/.local/state/monocode-fork/chrome/<slug>`). A session open in one window is never opened in another: the other window is brought forward instead. Off under `vitest`. Hooks: `sessionStore.ts` (`storeCommand` on the four snapshot/in-flight calls), `App.tsx` (`useWindowSessions`, guard in `onSelectHistorySession`), `UsageFooter.tsx`, `ForkTitle.ts`, `lib.rs` (init, reopen at Ready, `window_destroyed`), `menu.rs`. |
| Ring at my places | `src/fork/location` + `src-tauri/src/fork_location.rs`: alert sounds (banner sound and in-app cues) play only at saved places; elsewhere banners still show, silently. Places and the mode (At my places / Always / Never) live in `~/.local/state/monocode-fork/places.json`, outside the repo since they hold addresses. CoreLocation gives the fix every 3 min (needs Location Services for MonoCode; a fix older than 15 min counts as unknown = silent); CLGeocoder looks up typed addresses. A place matches within its radius (default 150 m) plus up to 100 m of fix error. No file = upstream ringing. Footer button shows the place or "Silent" and edits places. Off under `vitest`. Hooks: `notifications.rs` (`show_notification` sound), `sounds.ts` (`playCue`), `UsageFooter.tsx`, `icons.tsx`, `lib.rs` (start at Ready), `Info.plist` + `Entitlements.plist` (location). |
| Chrome for Claude | `buildClaudeSpawnArgs` in `claudeProtocol.ts` passes `--chrome` to interactive Claude sessions, so they get the Claude in Chrome extension tools (headless `claude` leaves them out otherwise). MonoCode's own helper calls (titles, summaries) stay without it. |
| Update from the Dock | `src-tauri/src/fork_update.rs`: the installed app (only `/Applications/MonoCode.app`, never a dev build) runs `monocode --update` at launch, so `update.sh` builds and stages a new version however MonoCode was opened, and `monocode --after-quit PID` as it quits, which waits up to 60 s for the app to be gone and swaps the staged build in. Results go to `update.log` (`installed <sha>` or `install failed: ...`). Hooks: `lib.rs` (Ready, Exit), `window.rs` (`confirm_quit`). |
| Project bots | `src/fork/projectBots`: nine 8×8 bots join the mascot roster, one per own project (morgue tomb, jobbird bird, kairos hourglass, samridhlimbu spiky, clupai-monorepo chip, hoddle owl, panoptic eye, monocode cyclops, ripple drop). Each project gets its bot once at launch (`monocode.fork.projectBots.applied`); a later pick from the project menu wins. Hashed defaults never pick a bot. Hooks: `projectMascots.ts`, `pixelMascots.ts`, `App.tsx`. |
| Stylist Mono | `src/fork/stylist`: a Mono named Stylist (beret mascot) whose only job is each project's look. Made once at launch while Monos are on; every local project is handed to it the first time it is seen, a project taken off it stays off, and deleting it keeps it gone. It finds a project's real logo read-only, or draws a new SVG icon in its own `icons/` folder under the app data Monos folder, then sets logo, color, mascot and label through `/operator` actions: `projects.look`, `projects.look.set`, and `projects.logo.set`, which accepts files from that icons folder. Its standing instructions seed its SOUL.md once; edit them there. Ask it "do all projects" or "new icon for X". Hooks: `agentApp.ts`, `control_cli.rs`, `agentProjectLogos.ts`, `projectBots.ts` (beret), `App.tsx` (seed). |
| Vivobook agent | `src/fork/vivobook` + `fork/vivobook/vivobook-agent` (symlink in `~/.local/bin`): a "Vivobook" provider in the model picker runs Claude Code on the home-lab Vivobook over Tailscale SSH, in the same `$HOME`-relative project folder. The gateway starts Tailscale if it is off, checks SSH login (BatchMode, no prompts), the folder and `claude` there; on a failure it runs one local Claude fixer (Sonnet, Read plus Tailscale/SSH/git commands only, 240 s), checks again, and if still failing exits so the session does not open, showing its `Vivobook:` reason. Edits land in the Vivobook's copy; sync with git. Logs in `~/.local/state/monocode-fork/vivobook/`. Env: `VIVOBOOK_HOST`, `VIVOBOOK_NO_FIX=1`, `VIVOBOOK_FIX_SECONDS`. Hooks: `claude.ts` (`setClaudeVivobookThread`), `register.ts`, `harness.rs` (`harness_resolve_vivobook`, marker check). |
| Close to free memory | `src/fork/sessionClose`: a hover X on a loaded session row, a "Close to free memory" menu item, and a sweep button with a count (every idle session off screen) close a conversation without asking. Its agent CLI stops (`stopHarnessSession`, so the resume id stays), it is saved and leaves its tab and memory, and stays in the list; the next message resumes it. Sessions that are busy, waiting on input, holding a draft, queue, usage limit or provider switch, Monos, inbox asks, orchestration workers, leads of running runs, the session beside a Mono, and sessions an open plan, agent or changes tab reads stay open. Hooks: `App.tsx` (`onCloseSessionsForMemory`), `Sidebar.tsx` (rows, menu, button), `icons.tsx` (`Sweep`). |
| Resizable sidebar | `src/fork/sidebarSplit`: drag the gap under Monos and under Projects in the inset sidebar (no visible divider; double-click resets, arrow keys once focused). Caps 30% and 50% of the sidebar; heights and the sidebar width persist (`monocode.fork.sidebar.*` in localStorage); in a shorter window the resized sections shrink before the session list drops under 160 px. Hooks: `Sidebar.tsx`, `ProjectsList.tsx`. |
| New layout | Upstream's opt-in inset layout uses the Projects list above; dense session rows retain Safe/Handover/Not safe and message badges, and the close-all-safe button stays beside the Sessions filter. Footer buttons, claims tags and the window title remain available. |

- State and log: `~/.local/state/monocode-fork/` (`update.log`, staged `MonoCode.app`, `built-sha`, `installed-sha`).
- Skips when the repo is not on `mine` or has uncommitted changes, so it never fights a session working here.
- Settings and sessions live in `~/Library/Application Support/com.monocode.desktop` and survive every swap.
- Keep fork features in their own files where possible; fewer conflicts with upstream.
- The built-in updater has no endpoint in source builds, so it never replaces this build with the official one.
