### Dispute Rulings

**D1. Progress visual**
* **Verdict:** Sidebar row needs-you badge + plain text "3 of 10" on home; cut segmented bars and rings entirely.
* **Reason:** Milestone phases have wildly unequal weights, making partial-fill rings and bars deceptive confidence theater.

**D2. Done-when criteria**
* **Verdict:** Display-only text updated by agents via tool; strictly non-tickable by Sam on the dashboard.
* **Reason:** *Changed mind from interactive toggles:* Acceptance criteria ("feels good") are not tasks, and dual checklists diverge instantly.

**D3. Who sets phase status**
* **Verdict:** A human or trusted agent marks it; live signals only suggest, and `plan.md` loses status authority.
* **Reason:** Pure derivation fails on squashes, rebases, and soak tests, while manual markdown tables breed unparseable novellas.

**D4. Chat strip (layout B)**
* **Verdict:** Keep strictly as `"Phase N · name + needs pill"`, dropping the mini progress bar.
* **Reason:** Sub-chats need immediate milestone orientation and blocker awareness, not ten pixels of duplicated progress chrome.

**D5. Tapping a "Waiting on you" item**
* **Verdict:** Jump directly into the linked chat with the item and input focused.
* **Reason:** *Changed mind from inline resolution:* Safely unblocking an agent always requires reading its immediate preceding context.

**D6. "Start phase"**
* **Verdict:** Opens a chat seeded with the phase brief and done-when criteria, without pre-assigned branch ceremonies.
* **Reason:** Removes kickoff friction while letting agent worktree conventions adapt naturally to the task.

**D7. Which phases are expanded**
* **Verdict:** Every phase with an active session or an open ask is expanded.
* **Reason:** *Changed mind from "current phase only":* Yap proves concurrent phases run simultaneously; hiding non-current phases conceals live bottlenecks.

**D8. Handoff**
* **Verdict:** Both: top-level project `handoff.md` strip plus the latest agent status-note quoted inside each open phase card.
* **Reason:** The top strip answers macro project direction, while per-phase quotes explain what active agents are doing right now.

**D9. Anything ALL four missed that Sam needs?**
* **Verdict:** An aggregated live token burn / runaway spend meter and panic pause button across concurrent sessions.
* **Reason:** When running 15 background agents across worktrees, Sam needs to spot looping, token-burning agents from his phone before checking status.

### Single Weakest Argument in the Other Answers

**Model C's proposal to resolve "Waiting on you" items inline without opening the chat transcript.** 
Treating approval gates and device verifications like trivial inbox checkboxes encourages blind approvals; unblocking an AI agent without viewing its preceding tool output is a recipe for undetected hallucinations and broken code.
